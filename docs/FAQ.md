# 常见问题(FAQ)

## 隐私与安全

**Q:我的聊天记录会被传到哪去?**
默认**不出本机**:消息、报告、会话都存在 `data/`。只有当你配置了模型接口并触发总结/问答时,
**检索命中的那部分消息文本**会发给你选择的模型服务商。链接抓取、图片识别同理(都是你开的功能才跑)。

**Q:机器人会在群里说话吗?**
不会。推送默认只发私聊(`push.group_id = 0`);群内问答默认关闭,打开后也只在白名单群里、
且消息带触发前缀(默认 `问`)时才回应。

**Q:控制台能不能从外网访问?**
默认只监听 `127.0.0.1`,设计上就是"本机工具"。远程访问请走 SSH 隧道、`adb forward`,
或自己加一层带认证的反向代理。不要把 8091/8080 直接暴露到公网。

**Q:令牌泄露了怎么办?**
改 `data/config.json` 里的 `web.token`(或控制台「设置」页),然后 `qqops restart`。
旧令牌立即失效。

**Q:陌生人私聊机器人会消耗我的额度吗?**
不会。聊天问答有白名单,默认**只有「推送」里配置的主人 QQ**能用;既没配白名单也没配主人时,
一律不响应。真机上实测过:陌生人来私聊只会被计数为 `skipped`,不会调用模型。

## 成本

**Q:一天要花多少钱?**
取决于模型、消息量、总结频率。参考量级:一个 6 群、日活几百条的账号,每天总结一次
(结构化抽取 + 报告),用便宜模型约几分钱到几毛钱。控制台「任务」页有每次运行的 token 与费用,
`qqops summary --dry-run` 只组装提示词、**不产生任何费用**。

**Q:怎么省?**
- 提高 `schedule.min_new_messages`(没新消息就不跑);
- 缩小 `summarizer.window_hours`、`max_messages`;
- 关掉不常用的补料(`enrich.vision/files/links`);
- 功耗档位选 `saver`(顺带把富化推到夜间窗口)。

## 性能与保活

**Q:手机上内存占用多少?**
单进程模式实测约 **27~33 MB**;拆成四个进程约 **105 MB**(每个进程都要付一份解释器开销)。
默认在 Android 上自动选单进程。见 [POWER.md](POWER.md)。

**Q:进程老是被杀?**
Android 的三个主因(幽灵进程查杀、Doze、无自启)都有对策,见 [DEPLOY.md](DEPLOY.md) 第 1.4 节;
`qqops doctor` 会逐项体检并给出要执行的命令。

**Q:能不能用 Docker?**
非 Android 平台可以用,但本项目不需要容器:它没有依赖、没有编译步骤。Android 上不能跑 Docker,
所以才走 Termux + proot 这条路(NapCat 在 proot 里,QQOps 在 Termux 里)。

## 功能

**Q:为什么"零依赖"?装个包不是更简单吗?**
手机上 `pip install` 经常失败(缺编译环境、空间紧张),而"装不上依赖 = 整个程序不可用"。
所以核心只用标准库。唯一可选件是 PDF 解析(`pip install pypdf`),不装也只是 PDF 读不了。

**Q:支持别的平台吗(Telegram/Discord/微信)?**
目前适配层是 OneBot v11,协议侧任何实现(NapCat、Lagrange 等)都能接。别的平台需要新增适配器,
`adapters/` 就是为此留的位置。

**Q:JSON 卡片 / Markdown 卡片为什么显示"卡片版本过低"?**
新版 QQ 要求卡片数据**带签名**,自己拼的 JSON 卡片会被判为"版本过低";
markdown 与小程序卡片则依赖 NapCat 的 PacketBackend,而它对 QQ 版本有范围限制。
结论、证据与替代方案(合并转发卡片、官方分享卡片)见 [CHAT.md](CHAT.md)。

**Q:AI 回答会不会编造?**
提示词强制"只依据检索到的记录作答、每条结论标注来源编号"。控制台里每个编号都能点开原文核对;
模型不可用时会**降级为直接列出检索到的记录**,而不是编一段话。

**Q:数据存在哪?怎么备份/迁移?**
全部在 `data/`。`qqops backup` 生成 `data/backups/messages-<时间>.db`;
迁移就是"拷 `data/` 到新机器"。升级程序时**不要动 `data/`**。

## 开发

**Q:怎么加一个插件?**
参考 `qqops/plugins/reminders`(最小完整例子):`metadata.json` + `_conf_schema.json` + `__init__.py`,
用 `@register` 声明、`@route` 加接口、`@command` 加命令、`@task` 加定时、`@on_stage`/`@on_event` 挂事件。
放进 `plugins/` 目录重启即可被加载;控制台「插件」页能看到状态与配置表单。

**Q:为什么注释和日志都是中文?**
使用者看的就是中文控制台与中文日志;报错信息直接可读,比英文堆栈更省事。代码结构(命名/分层)仍是常规英文。
