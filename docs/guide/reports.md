# 总结与报告

"总结"是这台机器的核心产出:把一段时间里的群消息, 变成**事件、待办、链接、共识、记忆**,
并写成可以直接看的报告。

## 一次总结都发生了什么

```
取消息(按群/类型/时间窗)
   └─▶ 补料: 图片多模态识别 / 文档解析 / 链接正文抓取(都有配额与缓存)
        └─▶ 结构化抽取: 模型输出 JSON(事件/待办/链接/事实/记忆)
             ├─▶ events 表(去重合并, 可在「数据 → 事件」勾完成/忽略)
             ├─▶ memories 表(每群滚动记忆, 下次注入提示词 → 跨天连续)
             ├─▶ 报告: Markdown + 自包含 HTML(+ Excel/Word 导出)
             └─▶ 推送(可选): 私聊一段摘要 + 报告链接
```

## 三种触发方式

| 方式 | 位置 | 说明 |
|---|---|---|
| 定时 | 「任务」页 / 配置 `schedule` | 每天定点(可多个时间) / 每隔 N 分钟 / 每周几;可选"没新消息就跳过" |
| 立即 | 「任务」页「立即总结」/ `qqops summary` | 跑一次, 会推送(除非加 `--no-push`) |
| 试运行 | 「任务」页「试运行」/ `qqops summary --dry-run` | 只组装提示词,**不调用模型、不花钱** |

推荐的排查姿势:先「试运行」看提示词里是不是你想让它看的内容, 再真跑。

## 报告长什么样

- **Markdown**:`data/reports/summary_<时间>.md` —— 纯文本, 任何编辑器都能看;
- **自包含 HTML**:同一个名字的 `.html`, 样式与内容都在一个文件里, 手机上直接打开就是网页;
  控制台「总结」页的「网页版」链接走 `/r/<文件名>?token=…`;
- **Excel / Word**:报告页与运维页可导出 `xlsx`/`docx`(纯标准库手写 OOXML, 不需要 Office)。

报告内容分群组织:亮点、事件、待办、链接、值得记住的事实、该群记忆。

## 推送

配置 `push`:

| 键 | 说明 |
|---|---|
| `enable` | 是否推送 |
| `user_id` | 推给谁(**私聊**;建议填你自己) |
| `group_id` | 推给群(留 0 = 只在私聊发;非 0 会真的在群里发言) |
| `format` | 形态:`text` 纯文本 / `forward` 合并转发卡片(各版本可渲染) / `markdown` Markdown 卡片(需 QQ 版本支持) |
| `report_link` | 末尾附报告页链接(局域网地址, 手机本机可直接点) |
| `max_chars` | 单条上限, 超长自动分段 |
| `napcat_api_port` / `token` | 与 NapCat 的 `httpServers` 保持一致 |

::: warning 卡片形态的现状
新版 QQ 的自定义 JSON 卡片需要签名;`forward`(合并转发)各版本都能渲染, 是最稳的富文本形态。
原因与实测见[卡片与聊天问答](/CHAT)。
:::

## 长期记忆与个人档案

- **每群记忆**(`data/memories`, 也可在「数据 → 记忆」看):每次总结更新, 下次注入提示词,
  所以它能"记得上次聊到哪"。每条都有「看原文」, 给出该群最近消息作为核对依据;
- **个人档案**(「设置 → 个人档案」或 `data/profile.md`):写清你关注什么、长期目标、输出偏好,
  抽取时作为背景注入, 用来判断"哪些事与我有关"。

## 成本控制

| 手段 | 做法 |
|---|---|
| 先看提示词 | `--dry-run`, 不花钱 |
| 少跑 | `schedule.min_new_messages` 设大一点;`skip_if_no_new=true` |
| 少发 | 缩小 `summarizer.window_hours` / `max_messages` / `max_chars_per_group` |
| 少补料 | 关掉不常用的 `enrich.vision/files/links` |
| 记账 | 「任务」页每次运行有 token 与费用;填了单价才有金额 |

::: tip 缓存是省钱的
同一张图片按 URL 缓存, 只识别一次;抓过的链接不会重复抓。所以"补料"的成本主要在**新内容**上。
:::

## 报告出不来怎么办

| 现象 | 处理 |
|---|---|
| 提示"模型未配置" | 「设置」填 `api_key`(或 `llm.api_key`);不填也能采集与检索 |
| 报告只有统计没有内容 | 模型返回非 JSON 时会**降级为统计报告**;看「任务」页详情与日志 |
| 推送失败 | 检查 `push.token` 与 NapCat 的 `httpServers` 是否一致;`qqops logs scheduler` |
| 内容明显不对/漏 | 先看「试运行」的提示词;再看报告里的来源编号是否对得上 |
