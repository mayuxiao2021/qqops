# 提醒与待办

内置的 `reminders` 插件会从消息里认出"带时间点的待办", 到点提醒你。

## 它认什么

从群里的话里抽时间点, 例如:

```
"下周三之前把实验报告交了"     → 截止: 下周三
"明天 10 点开组会"            → 截止: 明天 10:00
"这个月月底前交材料"           → 截止: 月底
```

抽出来的条目进入**只追加的收件箱**, 由定时任务消费(单写者状态, 不会重复提醒)。

## 配置

控制台 → 插件 → 截止提醒:

| 项 | 说明 |
|---|---|
| 启用识别 | 关掉只保留手动新增的事件 |
| 关键词 / 群范围 | 只在这些群里、命中这些词时才识别 |
| 提前提醒 | 提前多少分钟提醒(0 = 到点才提醒) |
| 推送 | 是否通过 NapCat 推送到 QQ(默认关) |
| 目标会话 | 推送目标(留空 = 用「推送」里的主人 QQ) |

## 在控制台看

「数据 → 事件/待办」页:

- 按状态(进行中/已完成/已忽略)、类型、群、关键词筛;
- 勾完成 / 忽略 / 编辑 / 删除;也可手工新增;
- 顶部 KPI:进行中、7 天内到期、已过期、已完成;
- 导出 Excel/Word(也可直接给报告用)。

事件来源有两种:总结时从消息里**自动抽取**(结构化 JSON), 以及你**手工新增**。
同一个事件重复出现会**去重合并**(并累加置信度), 不会变成一屏重复条目。

## 命令行

```bash
qqops extras                        # 看旁路服务(含提醒插件的推送依赖 NapCat)
# 提醒本身的开关在插件配置里(控制台 → 插件 → 截止提醒)
```

插件的定时任务是 `reminders_tick`(每 60 秒), 在「插件」页能看到它的运行情况。

## 和其它功能的关系

| 功能 | 关系 |
|---|---|
| 总结 | 总结会顺带抽事件/待办;提醒插件是另一条独立通路(更快, 不等定时总结) |
| AI 问答 | 待办会作为来源之一(`[E1]`), 所以"有哪些快到期的"可以直接问 |
| 推送 | 提醒的推送走 NapCat API, 与报告推送共用一套发送出口 |

## 常见问题

| 现象 | 处理 |
|---|---|
| 该提醒的没提醒 | 看「插件」页 `reminders_tick` 是否在跑;确认消息群在插件配置的群范围内 |
| 提醒重复 | 正常不会(状态是单写者 + 去重);复现请带消息原文提 issue |
| 抽错了时间 | 在「数据 → 事件」里改;或把该群移出识别范围 |
