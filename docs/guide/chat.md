# AI 智能查询

用一句话问你的记录, 例如:

- 「昨天群里谁提到过报告?」
- 「我们最近在讨论什么?有没有快到期的待办?」
- 「上周分享的那个链接讲了什么?」

答案**必须标注来源编号**(如 `[M3]`), 点开就能看到原文 —— 这是它和"随便问个 AI"最大的区别。

## 它是怎么回答的

```
你的问题
  └─▶ 解析时间范围("昨天"→48h)与群范围
       └─▶ 在本地库里检索(中文 2 字滑窗 + 无分词库;命中不足时逐词再检索)
            └─▶ 把记录排成编号上下文: [M1] 10-10 12:03 群/昵称: 内容
                 └─▶ 模型只依据这份上下文作答, 每条结论带来源编号
                      └─▶ 结果与来源一起落库(会话可回看、可核对)
```

三条硬规则(写在系统提示词里):

1. **只依据检索到的记录作答**, 不得用常识补全;
2. **每条结论标注来源编号**, 编号必须真实存在;
3. 记录不足时**直说"记录里没有"**, 并指出还缺什么线索。

## 在控制台用

1. 打开「对话」页 → 输入问题(Enter 发送, Shift+Enter 换行);
2. 回答里的 `[M1]` 可点, 弹出**原文**(时间/群/昵称/正文, 是否撤回等);
3. 回答下方有来源芯片(💬消息 📌待办 🧠记忆 🔗链接 🖼媒体), 悬浮显示摘要;
4. 时间范围可选(默认 / 近 24h / 3 天 / 7 天 / 30 天 / 一年);
5. 左侧是会话列表:可以新建、切换、删除;**同一会话里能追问**("那昨天呢")。

空态会给 4 条**从真实记录生成的推荐问题**(不调用模型, 不花额度)。

## 追问与多轮

同一个会话里的多轮共享上下文 —— 助手会带上上一轮的检索结果继续问, 所以"它/那个/再往前"这类
指代能接上。想换话题建议新建会话, 避免污染上下文。

## 额度与成本

| 配置 | 默认 | 说明 |
|---|---|---|
| `basic.daily_quota` | 100 | 每天最多提问次数(**控制台与 QQ 问答共用**) |
| `basic.max_sources` | 60 | 最多送多少条记录给模型(越多越全, 也越贵) |
| `basic.max_rounds` | 2 | 模型发现信息不够时可以要求再检索一轮 |
| `basic.max_tokens` | 1500 | 单次回答上限 |

达到额度会明确提示, 不会静默失败。「对话」页左侧显示"今日已用 x/y"。

## 模型怎么配

优先用 `llm` 段(「设置 → AI 模型」);它留空时**自动回落到 `summarizer` 段**
(`base_url`/`api_key`/`model` 只维护一份)。任何 OpenAI 兼容接口都能用。

模型不可用时**不留白**:会把检索到的记录直接列出来并说明"模型不可用",
所以"能用"和"好用"是两件事 —— 前者不依赖模型。

## 与其它功能的关系

| 功能 | 关系 |
|---|---|
| 总结 | 共享同一批记录与同一套检索;总结产出长期记忆, 问答会把记忆也当来源(`[Y1]`) |
| QQ 里直接问 | 同一套引擎, 只是入口在聊天窗口;见[在 QQ 里直接问](/guide/qq-chat) |
| 群组开关 | 「群组」页只影响**总结**;问答在检索时按你问题里的群/时间范围取数 |

## 常见问题

| 现象 | 处理 |
|---|---|
| 说"记录里没有" | 换个时间范围或关键词;确认该群的消息确实入库了(「消息」页搜一下) |
| 答案不准 | 点开来源编号核对原文;来源对不上就带问题+来源提 issue |
| 提示模型不可用 | 检查 `api_key`/`base_url`;「任务」页与日志里有具体错误 |
| 想让回答更简短 | 在插件配置的「提示词 → 附加要求」里写, 例如"用要点列出, 不要寒暄" |
