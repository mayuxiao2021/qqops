# 消息与全文检索

消息页回答的是"群里到底说过什么"。数据来自 NapCat 的上报, 存在本机 SQLite 里, 不经过任何云。

## 采集范围由三处共同决定

| 位置 | 作用 |
|---|---|
| 「群组」页的勾选 | **参与总结**的群(唯一准绳, 决定总结与分析哪些群) |
| 配置 `collector.groups` | 采集阶段的**过滤**:只收这些群;留空=全部收 |
| 配置 `collector.kinds` | 采集阶段的类型过滤(如 `text,image`);留空=全部收 |

::: tip 两个"群过滤"的区别
`collector.groups` 是"要不要存", 「群组」页勾选是"要不要总结"。
想"全都存下来以后搜, 但只总结几个群"就把 `collector.groups` 留空, 然后在「群组」页只勾那几个。
:::

## 全文检索怎么用

1. 「消息」页顶部输入关键词 → 点「筛选」(或回车);
2. 命中词会**高亮**;右侧药丸显示当前检索方式:`全文索引`(FTS5) / `模糊匹配`(LIKE) / `按时间`;
3. 再叠加时间窗(近 1 小时 ~ 近 30 天)、群、类型, 都能组合。

中文检索是**按字匹配**的:输入"预算表"能命中"这次报告要加一页预算表", 不需要分词库。
英文/数字按前缀匹配。

::: details 为什么中文要特殊处理
SQLite 的 `unicode61` 分词器会把一整串中文当成一个 token, 所以 QQOps 在索引侧给中文字之间插空格、
查询侧用短语匹配。检索不准时点「运维 → 重建全文索引」(或 `qqops reindex`)。
:::

## 消息行上的标记

| 标记 | 含义 |
|---|---|
| **已撤回** | NapCat 上报了 `group_recall`, 消息仍在库里但标记为撤回(记录不删) |
| **机器人** | 机器人自己发的消息(`message_sent`), 用于对话上下文 |

点任意一行看详情:时间、群、发送者、类型、原文(含 CQ 码原样)。

## 导出

- 「消息」页的「导出表格」→ `CSV`(带 BOM, Excel 直接双击能打开, 中文不乱码);
- 「运维 → 备份」页还能导出最近报告 Word、事件/链接 Excel。

```bash
qqops export.csv --hours 168 > 最近一周.csv   # 命令行等价物
```

## 入库与去重规则

| 情况 | 处理 |
|---|---|
| 同一条消息被重复上报(断线重连补发) | `(group_id, message_id)` 唯一索引 + `INSERT OR IGNORE`, 只存一条 |
| 空消息(无文本也无消息段) | 丢弃, 计入 `skipped` |
| 私聊消息 | 默认**不入库**(隐私);但要交给插件, 所以仍会发事件(见下) |
| 事件时间落在未来 >1 天 | 改用本地时间(手机上时钟回拨很常见) |
| 请求体超过 8MB | 直接 413 且不读请求体 |

采集指标在「运维 → 服务」页底部:收下 / 跳过 / 拒绝 / 错误 / 重复 / 通知 / 心跳 / 自发。

::: tip 私聊为什么"不存但要处理"
`collector.store_private=false`(默认)时私聊内容不入库。但「在 QQ 里问 AI」需要看到私聊消息,
所以采集器会给它打一个"未入库"标记后交给插件 —— 内容只在内存里过一遍。
想连私聊内容一起存(一起进总结), 打开配置里的「也保存私聊消息」。
不想让私聊触发问答, 关掉「私聊不入库也交给插件」。
:::

## 常见问题

| 现象 | 处理 |
|---|---|
| 消息量不涨 | `qqops doctor` 看采集口;确认 NapCat `httpClients` 指向 `127.0.0.1:8080` 且已重启 |
| 搜不到明显存在的词 | 点「重建全文索引」;确认时间窗没把消息排除在外 |
| 群里消息缺失一部分 | 看采集指标里的 `skipped`;检查 `collector.groups/kinds` 过滤 |
| 同一句话出现两次 | 正常情况不会(唯一索引去重);若出现请带 `message_id` 提 issue |
